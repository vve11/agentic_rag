## 2. 正文版本一：直接发布版

```text
最近整理了一个我自己很喜欢的 AI 项目：

Paper RAG Agent
一个面向论文研读场景的 RAG + Agent 项目。

它不是普通聊天机器人，
也不是那种“接一个大模型就开始回复”的智能客服模板。

它更像是一个论文研读工作台：

可以导入论文，
可以围绕论文内容提问，
可以展示回答引用的证据，
可以整理成 Wiki / 知识笔记，
也可以作为一个完整 AI 应用项目来演示。

我觉得它很适合两类人：

1. 想系统学习 RAG + Agent 的同学
2. 想准备一个能写进简历、面试时能讲清楚的 AI 项目的人

和智能客服类 Agent 不一样：

智能客服更偏业务接待、FAQ 回复、售前售后流程；
这个项目更偏知识研读、论文问答、证据引用和面试表达。

所以它不是只为了“能聊天”，
而是为了让你能讲清楚：

我做过一个完整的 AI 应用，
它有场景、有前端、有后端、有资料管理、有问答效果，也有可展示的结果。

完整学习版会包含：
项目源码、运行手册、RAG+Agent 学习手册、演示问题、简历表达、面试准备和常见报错排查。

公开帖里我不会展开具体实现细节，防止直接变成免费复刻教程。

如果你也想做一个能用于面试的 RAG + Agent 项目，可以先收藏。
```

## 3. 正文版本二：更种草版

```text
说实话，现在很多 AI Agent 项目都太像了：

套一个聊天框，
接一个大模型，
再加几个工具调用，
最后写在简历上叫“智能助手”。

但面试的时候很容易被问住：

这个项目到底解决什么问题？
和普通智能客服有什么区别？
为什么不是简单调 API？
它能不能作为一个完整 AI 应用来展示？

所以我做了一个不太一样的方向：

Paper RAG Agent
一个面向论文研读的 RAG + Agent 工作台。

它的场景不是售前售后客服，
而是帮助用户围绕论文进行问答、整理、引用和知识沉淀。

前端做成了工作台页面，
不是只在命令行里跑；
项目也不是只展示“模型会回答”，
而是更强调“这个回答来自哪里、能不能作为学习和面试展示材料”。

比较适合：

1. 想学 RAG 的同学
2. 想学 Agent 应用开发的同学
3. 简历里缺少一个完整 AI 项目的人
4. 不想再写普通智能客服 demo 的人
5. 想在面试里讲清楚项目边界的人

这个项目的重点不是炫技，
而是把一个 AI 应用从界面、资料、问答、引用、反馈和演示体验串起来。

完整学习版会包含：
项目源码、
运行手册、
RAG+Agent 学习路径、
标准演示问题、
简历表达建议、
面试准备材料、
常见报错排查。

公开内容只展示项目方向，不展开完整实现路径。

感兴趣可以先收藏，后面我继续更新项目展示。
```

## 4. 正文版本三：克制专业版

```text
分享一个我最近整理的 AI 项目方向：

Paper RAG Agent
一个面向学术论文研读场景的 RAG + Agent 项目。

这个项目不是智能客服，也不是普通聊天机器人。

相比常见客服 Agent：

Paper RAG Agent 更关注知识型问题、文档理解、证据引用和面试表达。

我觉得它适合作为 RAG + Agent 学习项目，也适合放进简历里作为 AI 应用项目来讲。

因为它不是只证明“我会调模型 API”，而是能展示一个 AI 应用从界面、资料、问答到结果呈现的完整形态。

这条只做项目展示，不展开具体实现细节。
```
